# LTX-Video 2B (0.9.8 distilled) on ILGPU.ML: the next video model

Decided 2026-10-22 (TJ: "editor's choice on the next video model"; the choice is Tuvok's).

## Why this one
The goal for video is the maximum that runs in a BROWSER tab, and the candidates differ a lot in that:

| Model | Size | Browser fit | Notes |
|-------|------|-------------|-------|
| Wan 2.2 A14B (MoE) | two 14B experts (7 GB each at 4-bit), Wan2.1 VAE (16 ch, 4x8x8: 4x the tokens of the 5B per picture) | no | a second VAE to port, a second text-conditioning path; the 5B Turbo already makes clean 720p |
| LTX-2.5 (open weights since 2026-08-11) | 22B joint audio-video DiT (distilled: 8 steps, no CFG), Gemma 4 12B text encoder, audio VAE + vocoder, x2 latent upscalers | no on a 12 GB card in a tab (22B is 11 GB even at 4-bit) | desktop streaming is possible later; our Gemma 4 code helps the text side. Licence: LTX-2.x Community (free under $10M revenue) |
| **LTX-Video 2B 0.9.8 distilled** | 2B DiT (28 layers, dim 2048), T5-v1.1-XXL encoder, VAE 32x32x8 compression with 128 latent channels | **yes** | 6.3 GB single file (bf16); distilled = few steps, no CFG; 704x480 x 121 frames is only about 5,300 tokens (Wan 5B at the same clip: 27k at 720p), so a 5 s clip is cheap |

LTX-Video's 2B is the model whose cost structure fits the tab: few tokens (a heavily compressed VAE does the work), a small DiT, 8 steps or fewer, one forward per step. It also reuses what we have: T5 encoder code (the Wan umT5 port: gated-GELU T5, small differences below), DiT kernels (adaLN, RMS-norm q/k, attention, GELU-tanh FFN), the Conv implicit GEMM and fp16 caches for the VAE.

## Model facts (read from diffusers 0.41 `transformer_ltx.py`; to be re-verified against the reference outputs stage by stage)
- DiT `LTXVideoTransformer3DModel`: in/out channels 128, patch 1x1x1 (every latent position is a token), 32 heads x 64 = 2048, 28 layers, cross-attention dim 2048, text width 4096 projected by `caption_projection` (PixArtAlphaTextProjection: Linear, GELU-tanh, Linear), FFN 2048 -> 8192 GELU-tanh -> 2048, qk-norm `rms_norm_across_heads` (RMSNorm over the whole 2048 width of q and k, eps 1e-5, affine) BEFORE the head split.
- Block: `norm1` (RMSNorm, no affine) then `* (1 + scale_msa) + shift_msa` where the six adaLN values are a per-block `scale_shift_table[6, dim]` plus the shared time embedding (`AdaLayerNormSingle`: sinusoidal -> MLP -> SiLU -> Linear(dim, 6 dim)); self-attention with RoPE on q and k; `hidden += attn * gate_msa`; cross-attention to the text WITH the T5 padding mask (128 tokens padded, mask on the keys); `norm2` modulated by `scale_mlp / shift_mlp`, FFN, `hidden += ff * gate_mlp`. Output: `norm_out` (LayerNorm no affine), `scale_shift_table[2, dim]` + the time embedding, `proj_out` Linear(2048, 128).
- RoPE: computed in fp32 over the FULL inner dim (2048), not per head: the grid (frame, h, w) normalised by the base sizes (20 frames, 2048, 2048) times the VAE compression scales (8, 32, 32) times patch size, `freqs = theta^linspace(0, 1, dim/6) * pi/2 * (grid * 2 - 1)`, cos/sin repeated in INTERLEAVED pairs, `dim % 6` leading entries padded with cos 1 / sin 0.
- Text: T5-v1.1-XXL encoder (not umT5): the relative-position bias exists only in the first block and is SHARED by all blocks (umT5 has one per layer); 32128-token vocabulary; padded to 128 tokens; the mask goes to the DiT's cross-attention.
- Scheduler: FlowMatchEulerDiscrete; the 0.9.8 distilled recipe uses a fixed timesteps list (to be taken from the official `ltxv-2b-0.9.8-distilled.yaml`), guidance off, one forward per step.
- VAE `AutoencoderKLLTXVideo`: 128 latent channels, spatial compression 32, temporal 8 (frames = 8n + 1), causal 3D convolutions, a decoder conditioned on a timestep (`decode_timestep`, `decode_noise_scale` in the 0.9.x releases), depth-to-space upsampling. 1552 lines in diffusers: the biggest piece of the port.

## Files (Lightricks/LTX-Video on Hugging Face; public)
`ltxv-2b-0.9.8-distilled.safetensors` 6.34 GB (the single-file ComfyUI-layout bundle: transformer + VAE), also an fp8 4.46 GB; the text encoder is T5-v1.1-XXL fp32 in 4 shards (19 GB; the encoder alone as bf16 is about 9.5 GB, 8-bit about 5 GB), tokenizer `spiece.model` (we need the HF `tokenizer.json` of `google/t5-v1_1-xxl` for `UnigramTokenizer`), `scheduler_config.json`. The 13B and the older 2B releases are in the same repo (0.9.6 distilled is real-time capable per the card).

## Stages (each gated against the reference on identical inputs, parity first)
1. Reference environment: WSL `~/wan/venv` has diffusers 0.41, transformers 5.20, torch 2.6, sentencepiece; assets in `F:\Projects\ltx` (downloading). Dump per-stage fixtures with a `tools/ltx-harness/reference` set of scripts (as for Wan).
2. T5-v1.1-XXL encoder (adapt `UmT5Encoder`: shared bias, vocab, 128-token padding + mask output), bf16 / 8-bit export, tokenizer.
3. DiT (`LtxDiT`): safetensors export in our layout (fused qkv, kv), RoPE kernel on the full width, masked cross-attention, parity per block.
4. Scheduler + sampler loop (teacher-forced and free-running vs the reference).
5. VAE decoder (and the encoder for image conditioning): causal convs on the implicit GEMM, fp16 caches, chunked per latent frame.
6. `LtxPipeline`, console example, WPF example, `/video` page model picker, browser run on WebGPU, host the exports on `models.spawndev.com`.
7. Later: the 13B distilled and LTX-2.5 22B on the desktop by streaming, the spatial/temporal latent upscalers.
