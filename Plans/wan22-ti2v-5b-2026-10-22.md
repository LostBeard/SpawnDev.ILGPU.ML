# Wan 2.2 TI2V-5B (text and image to video) on ILGPU.ML

Started 2026-10-22. TJ's goals (2026-10-21): get it working IN THE BROWSER and squeeze as much capability out of ML there as possible, use it to put
SpawnDev.ILGPU through its paces (Data is standing by; the generated shaders are a source of insight), handle tight VRAM when it has to, and take what
the browser teaches back to the desktop. A browser demo page plus a console and a WPF example under `Examples/`. First model: **Wan2.2-TI2V-5B**
(Apache 2.0). Then the A14B mixture-of-experts models, then LTX 2.5 (19B, audio and video).

Everything below marked "source" was read from `Wan-Video/Wan2.2` (`wan/configs/wan_ti2v_5B.py`, `wan/modules/model.py`, `wan/textimage2video.py`) on 2026-10-22; "card" is
the Hugging Face model card. Nothing is ported yet.

## The model (source)

| Part | Facts |
|------|-------|
| DiT (`WanModel`, model_type `ti2v`) | dim 3072, ffn 14336, 24 heads (head dim 128), 30 layers, patch (1, 2, 2) via a Conv3d with kernel = stride (so a linear layer on patches), `qk_norm` (RMSNorm over the whole q and k vector), `cross_attn_norm` (LayerNorm with affine before the cross-attention), eps 1e-6, freq_dim 256, text_len 512, text_dim 4096 |
| Block | adaLN-style modulation: a learned `[1, 6, dim]` table plus the time projection, split into 6 (shift/scale/gate for attention and for the FFN); self-attention with 3D RoPE; cross-attention to the text (no modulation); GELU(tanh) FFN. The same shape as the FLUX / TRELLIS flow blocks we already run, with RMSNorm on q/k and a cross-attention |
| 3D RoPE | head dim 128 = 64 complex pairs, split `[22, 21, 21]` pairs for (frame, height, width); frequencies `theta = 10000`, computed in float64 in the reference |
| Time | sinusoidal(256) -> Linear -> SiLU -> Linear -> SiLU -> Linear(dim, 6 dim); **per token**: in TI2V the first latent frame is the conditioning image and gets timestep 0, every other token gets t. The reference materialises `e` as `[L, 6, dim]` float32 (2 GB at 27k tokens); only TWO distinct values ever occur, so compute the modulation twice and select per token |
| Head | LayerNorm, 2-entry modulation, Linear(dim, 4 * out_dim), unpatchify |
| Text | umT5-XXL encoder (`models_t5_umt5-xxl-enc-bf16.pth`), 512 tokens, then `text_embedding` MLP (4096 -> 3072). The text K and V of every block depend only on the prompt, so compute them once and reuse them for all steps and both CFG branches |
| VAE | `Wan2_2_VAE` (`vae2_2.py`), stride (4, 16, 16), 48 latent channels (`z_dim`), causal 3D convolutions decoded chunk by chunk with a feature cache |
| Sampling | `FlowUniPCMultistepScheduler`, shift 5.0, 50 steps, guidance 5.0 (two DiT forwards per step: conditional and unconditional), 121 frames at 24 fps, default 1280x704. Image conditioning: the image is resized and cropped to the output size, VAE-encoded, and `latent = (1 - mask) * z + mask * latent` after every step, `mask` zero on the first latent frame |
| Default negative prompt | a fixed Chinese prompt (in `shared_config.py`), so its umT5 embedding is a constant that can be shipped (512 x 4096 values) instead of computed |

## Cost model (my arithmetic; measure before believing)

Latent frames `Fz = (F - 1) / 4 + 1`, tokens `N = Fz * (H / 32) * (W / 32)`.

| Output | Frames | Tokens N |
|--------|--------|----------|
| 1280x704 | 121 | 27,280 |
| 960x544 | 49 | 6,630 |
| 640x352 | 121 / 81 / 49 / 33 | 6,820 / 4,620 / 2,860 / 1,980 |

Per forward, FLOPs: linear layers about `8.68e9 * N` (4.34B parameters in the blocks), self-attention `3.69e5 * N^2` (4 N^2 d per block, d = 3072, 30 blocks),
cross-attention about `1.9e8 * N`. A generation is 100 forwards (50 steps x 2 CFG branches).

Measured on the RTX 4070 on the TRELLIS.2 DiT (19,786 tokens, dim 1536, same head size 128): browser WebGPU 8 TFLOPS GEMM, self-attention 484 ms per block at
5.6 to 6.3 TFLOPS; CUDA with tensor cores 78 ms per block (about 31 TFLOPS) and about 35 TFLOPS GEMM. Scaling that:

| Where | Output | Per forward | 100 forwards |
|-------|--------|-------------|--------------|
| CUDA | 1280x704, 121 frames | about 16 s (GEMM 6.8 s, attention 8.9 s) | about 26 min on a 4070 (the card claims under 9 min on a 4090) |
| Browser WebGPU | 1280x704, 121 frames | about 85 s (GEMM 30 s, attention 55 s) | about 2.4 hours: not a browser target |
| Browser WebGPU | 640x352, 121 frames (6,820 tokens) | about 10 s | about 17 min |
| Browser WebGPU | 640x352, 33 frames (1,980 tokens) | about 2.4 s | about 4 min |

So the browser demo starts at 640x352 and 33 to 121 frames; the desktop does the full size. Levers beyond that: fewer UniPC steps (20 to 25), no unconditional
branch on some steps, a distilled few-step LoRA if one exists for the 5B (to check), the shader-level work with Data (attention is 80 % of a block and is the
kernel the browser is slowest at), and a better GEMM.

## Memory (tight VRAM is a requirement)

- DiT weights: 5B parameters = 10 GB bf16, 5 GB 8-bit, 2.6 GB 4-bit. WebGPU limits a binding to 2 GiB, so weights are per-tensor buffers (as for FLUX 3). Plan: our own 4-bit and 8-bit exports like FLUX 3's, streamed per stage from the models host, OPFS cache.
- umT5-XXL: about 5.7B parameters (1B of them the 256k-token embedding table) = 11 GB bf16. Run once per prompt, free before the DiT loads (the FLUX 3 caption writer pattern). Quantised GGUF/8-bit/4-bit variants; the negative prompt's embedding is shipped.
- Activations at 27k tokens: 335 MB per `[N, 3072]` float32 tensor, the FFN hidden `[N, 14336]` is 1.56 GB, so the FFN is chunked over tokens (the chunked decoder pattern from the TRELLIS.2 cascade). At 7k tokens everything fits comfortably.
- VAE decode: the dominant memory risk. Causal chunked decode with the feature cache, one latent frame (4 video frames) at a time, then the frames stream out.
- WebGPU command queue depth: wait for the device every step (the `FlowSampler.SampleAsync` lesson; a 25 s call queued 24 deep hung the device).
