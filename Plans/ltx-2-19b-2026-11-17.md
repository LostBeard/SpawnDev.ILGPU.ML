## RoPE, MEASURED against the dumped tables (11-17, all four 6e-8)
- Split layout: a frequency list of dim / 2 is cut per head (head h gets entries h * (D / 2) ..), and each head vector's first half pairs with its second half.
- freq_j = theta^(j / (F - 1)) * pi / 2 (float64, then float32), angle (2 frac - 1) freq_j in float32, theta 1e4.
- Video self-attn (4096 = 32 x 128): F = 4096 / 6 = 682 per axis, flattened FREQUENCY-major with the axis fastest (index j * 3 + axis), 2 entries (cos 1, sin 0)
  prepended -> 2048. Token coordinates: time midpoint of pixel frames [max(8 f - 7, 0), 8 f + 1) / fps (25) / 20; h, w: (32 h + 16) / 2048.
- Audio self-attn and audio cross (2048 = 32 x 64): F = 1024, frac = midpoint of [max(4 f - 3, 0), max(4 f + 1, 0)) x 160 / 16000 s / 20.
- Video cross (to audio, 32 x 64 heads): F = 1024 on the video token's time frac only.
- Connector (3840 = 30 x 128): F = 1920, frac = p / 4096.

## Where ComfyUI differs from diffusers' code (MEASURED 11-17 with float64 numpy references built from the taps + weights; follow ComfyUI)
- Gemma 3 RMSNorm: the scale 1 + w is formed in the weight's dtype (bf16), not fp32: fp32 leaves layer 0 2.6e-3 off, bf16(1 + w) 1.3e-7.
- DiT attention q / k RMS norms: epsilon 1e-5 (diffusers' default 1e-6): 1e-6 leaves block 0's video 1.9e-3 off, 1e-5 3e-7.
- DiT audio <-> video: v2a reads the video stream AFTER a2v's update (diffusers computes both norms first): audio 2.4e-4 -> 1.1e-7.
- Ruled out on the way (all worse): adjacent-pair RoPE, shift-first cross mods, per-head q / k norms, bf16 casts of mods / tables / temb / q, k / linear in or out /
  attention probabilities / gelu input / RoPE tables, erf GELU, Gemma eps 1e-5, relative Gemma positions.
- Dump quirk: modules that update their inputs in place (the DiT blocks) have "in" taps equal to their outputs (the hook saved after forward): use the previous
  module's output (block 0's input = patchify_proj's output).

- OPEN, library: DiTKernels' PreciseActivations tensor-core GEMM (bf16 x2 split) is ~10-70x less exact than the fp32 tiled GEMM on these shapes (projection K 188160:
  4.6e-4 vs 6.9e-6; caption projections 2e-5 vs 1.2e-6). Measure and fix before the LTX-2 release.
  Read 11-17: the activation hi / lo bf16 split in MmaGemm.KernelBf16x2Dense is correct (residual = x - bf16(x)), so the bits are not lost on input. Hypothesis: the tensor
  cores' fp32 accumulation truncates (not round-to-nearest) on Ampere / Ada, a biased error that grows ~K (K 188160 worst). Test: a K sweep (1k..200k) of the x2 GEMM vs float64,
  error vs K slope 1 = truncation. Fix if so: per k-step MMA into zeroed registers, then an RNE fp32 add into the accumulators (a "precise accumulate" variant).
